## 1. UI/UX設計

### 1.1 デザイン言語

Linear・Raycast・Vercel・Cursor・Claude・Notionを参照軸としつつ、本プロダクトは「AIエージェントが人の代わりに働いている様子を可視化する」という性質上、**放送局のコントロールルームのようなマルチパネルUI**が最も機能に合致します。

- **ダークモード基調**（ライトモードも用意するが既定はダーク）
- **コマンドパレット（⌘K）**でどの画面からもジャンプ可能に（Linear/Raycast踏襲）
- **等幅フォントのアクセント**：ログ・スコア・金額などデータ性の高い数値は等幅フォントで統一し、視認性とプロフェッショナルな質感を両立
- **モーション自体の質**：動画制作ツールなので、UI自体のトランジション・マイクロインタラクションも丁寧に作り込み、プロダクトの説得力に直結させる
- 日本語・英語混在を前提としたタイポグラフィ（見出しはInter/Geist、日本語本文はNoto Sans JP等、行間を広めに）
- フルレスポンシブ（スマートフォンでは「Control Room」はサマリーカード表示に簡略化）

### 1.2 主要画面

| 画面 | 内容 |
|---|---|
| **Studio** | 商品URL/画像アップロード→生成プレビュー。生成中はストリーミングでプレビュー更新 |
| **Portfolio Manager** | 生成済みポートフォリオサイトの一覧・公開URL管理・テーマ編集 |
| **Leads (Kanban)** | 発見済みリードをスコア順に一覧・カンバンで進捗管理、ソース元・同意ステータスをバッジ表示 |
| **Campaigns / Inbox** | 営業メッセージの下書き一覧・承認ボタン・送信後の返信スレッド管理 |
| **Deals (CRM)** | パイプライン形式の商談管理、金額・確度・次アクション |
| **Billing** | 請求書一覧、Stripeダッシュボードへのディープリンク |
| **Knowledge** | RAGソースの接続状況、インデックス済みドキュメント検索 |
| **Analytics** | 主要KPI（後述）のダッシュボード、AIによる改善提案カード |
| **Control Room** | 13エージェントの現在の稼働状況をリアルタイムパネル表示。Durable ObjectのWebSocketに接続し、実行中タスク・待機中の承認・直近のエラーを一望できる、本プロダクトの「顔」となる画面 |

### 1.3 Control Room画面のイメージ（React雛形の考え方）

`useAgent`（`agents/react`）で各エージェントDurable Objectに接続し、`onStateUpdate`で稼働状況をリアルタイム反映します。13エージェント分のパネルをグリッド表示し、実行中は薄いグロー、承認待ちは警告色、というように状態を色で即座に判別できるようにします。この画面のReactコンポーネント一式は、設計確定後にArtifactとして具体的に作成することも可能です。

## 2. 実装ロードマップ

### 2.1 フェーズ設計

| フェーズ | 期間目安 | 内容 |
|---|---|---|
| **Phase 0: 基盤** | 2〜3週間 | マルチテナント認証（Clerk）、Postgres+RLSスキーマ、Wrangler CI/CD、課金の骨格（Stripe連携） |
| **Phase 1: Motion Generator + Portfolio** | 3〜4週間 | プロバイダ1〜2社（例：Kling + Higgsfield）のみ接続、Prompt Builder〜Portfolio生成までの一気通貫。**ここが最大の価値提供ポイントなので最優先** |
| **Phase 2: Lead Finder（コンプライアント版）** | 2〜3週間 | 公式API/ライセンスデータプロバイダ経由のみ実装（詳細ドキュメント⑤）。CSVインポートも並行サポート |
| **Phase 3: Sales Agent（人の承認必須）** | 2週間 | メッセージ下書き生成＋承認UI＋送信キュー。自動送信は行わない |
| **Phase 4: CRM + 納品 + 請求自動化** | 3週間 | 商談パイプライン、Stripe請求、納品ワークフロー |
| **Phase 5: Analytics + Knowledge/RAG** | 2週間 | ダッシュボード、RAGソース接続、改善提案生成 |
| **Phase 6: スケール強化** | 継続 | 追加プロバイダ、マルチリージョン、エンタープライズ機能（詳細ドキュメント⑤） |

「営業メール送信の完全自動化」「数万社への同時アプローチ」はPhase 3以降でも既定オフとし、テナントが意図的に自動化度を上げられるオプトイン設計にすることを推奨します。

### 2.2 開発ワークフローそのものへの提案（Claude Codeの活用）

ご要望通りClaude Codeを開発の中心に据える前提で、現在のClaude Codeが提供する機能とこのロードマップの対応を整理します。

- **Subagents**：Claude Code内で「コードレビュー用」「テストカバレッジ確認用」「マイグレーション影響確認用」のように役割を絞ったSubagentを`.claude/agents/`配下に定義し、13エージェントそれぞれの実装を並列でレビュー・実装させることが可能です。各Subagentは独立したコンテキストウィンドウを持つため、メインの会話コンテキストを圧迫せずに大きめの調査・実装タスクを任せられます
- **Agent Teams**（複数のClaude Codeセッションをまたいだ協調）は、例えば「Phase 1のMotion Generator MCPチーム」と「Phase 2のLead Finderチーム」を並行して走らせるような、本プロジェクト規模のスケールで特に有効です
- 本ドキュメント一式（②のDBスキーマ・MCPツール定義、③のエージェント仕様）をそのまま`CLAUDE.md`やプロジェクトのコンテキストとして渡すことで、各Subagentが一貫した設計方針で実装を進められます

最新のSubagents/Agent Teamsの正確な設定方法は日々更新されているため、実装着手時に https://docs.claude.com/en/docs/claude-code/overview で最新のドキュメントをご確認ください。

## 3. MVP設計

「全部乗せ」を最初から作らないことが、実際にローンチできる確率を最も上げます。MVPは以下に絞ることを提案します。

### 3.1 MVPスコープ（含むもの）

- 商品URL/画像アップロード → 動画生成（プロバイダ1〜2社）→ 15/30/60秒バリエーション
- ポートフォリオサイトの自動生成・公開URL発行
- リードのCSVインポート（自動収集は次フェーズ）
- 営業メッセージの**下書き生成＋人力送信**（自動送信MCPは未接続でよい）
- 簡易CRM（商談ステージの手動更新）
- Stripeでの請求書発行（自動化はせず、ワンクリック発行）

### 3.2 MVPスコープ外（意図的に後回し）

- Lead Finderの完全自動収集（コンプライアンス基盤が整うPhase 2以降）
- 営業メッセージの完全自動送信
- 13エージェントすべての並列フル稼働（MVPでは5〜6エージェントで十分機能します：Prompt Engineer, Motion Designer, QA, Copywriter, Sales(下書きのみ), Automation）
- Slack/Discord/LINE/WhatsApp送信（まずEmailのみ）
- 多言語対応（まず日本語＋英語）

この絞り込みにより、Phase 0〜1で「動くプロダクト」を6〜7週間程度で立ち上げられる見込みです。

続けて `05-ops-security-compliance-cost.md` で本番運用・セキュリティ・コンプライアンス・コスト最適化・将来拡張をご覧ください。
